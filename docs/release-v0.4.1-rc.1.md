# v0.4.1-rc.1 测试冻结说明

## 定位

`v0.4.1-rc.1` 是 v0.4 世界模拟之后的阶段性稳定候选版，用于近期多轮真实 Provider 与长对话测试。冻结后以修复阻断问题、数据错误和明显体验回归为主，不在同一基线上继续扩张大功能。

## 冻结范围

- 剧本书架、内容包联动、自定义剧本和独立故事工程。
- 角色卡、世界书、Prompt、素材中心、导入预览和兼容性评定。
- 分层记忆、事实卡、事件账本、动作协议、世界状态裁定和多 NPC 模拟。
- Provider 测试连接、多模型任务路由、流式对话、重生成、Swipe 与消息编辑。
- 沉浸模式、结构化正文、推荐行动、主角与互动角色侧栏，以及题材化状态面板。
- 创作账本、场景章纲、叙事承诺和角色扮演响应协议。

## 本机数据边界

以下目录是个人导入素材和运行时数据，不进入版本库：

```text
data/assets/
data/library/
data/projects/
data/sessions/
data/config/providers.local.json
```

冻结提交只包含源码、测试、文档和内置默认内容。API Key、导入角色图片、社区素材与个人故事存档继续保留在本机。

## 重点测试

1. 使用至少两个 Provider 各完成一次测试连接、首次开局、流式续写和重生成。
2. 分别验证玄幻、仙侠、灵异、历史和英雄志剧本的主题、背景、世界书、角色与叙事路线同步。
3. 连续对话 20 至 50 轮，观察自动总结、事实提取、关系变化、Token 用量和上下文稳定性。
4. 验证推荐行动会被改写为符合主角身份、当前环境和叙事视角的自然行动，而不是原样发送标签文本。
5. 验证主角信息、互动角色、榜单、造化和记忆侧栏的结构化渲染、滚动与关闭重开。
6. 导入真实 Character Card V2 PNG 与世界书 JSON，检查图片提取、格式兼容、冲突提示和自定义剧本创建。
7. 执行会话导出、备份、恢复和旧数据迁移，确认当前故事与资源库不丢失。

## 问题记录建议

每次反馈至少保留：应用版本、Provider 与模型、剧本名、会话 ID、操作步骤、预期结果、实际结果和截图。涉及模型输出时，再附上该轮输入、可见输出以及是否发生流式中断。

## 验证命令

```bash
npm run backup -- --reason pre-v0.4.1-rc.1-test
npm run release:check
npm run start:local
```

测试完成并清理阻断问题后，再决定是否发布 `v0.4.1` 稳定版。
